# 飞牛安装包

FPK 依赖飞牛应用中心提供的 `nodejs_v22`，不在安装包内重复打包 Node.js。使用 `npm run pack` 构建时需要安装飞牛官方 `fnpack`。

输出文件名包含 manifest 中的版本号，例如 `version = 1.2.1` 时生成 `fpk/node-space-1.2.1.fpk`。同版本打包会替换已有文件，其它版本保留。发布时可将此文件作为 GitHub Releases 附件上传，不需要提交到 Git 源码仓库。

安装向导可选填写数据目录。留空时使用 fnOS 为应用分配的持久化目录 `TRIM_PKGVAR/data`；自定义时填入 NAS 绝对路径。生命周期脚本以 root 准备目录，Node 服务通过 run-as-user 切换到 node-space 应用账号运行。fnOS 1.1 配置 POSIX ACL 与上级路径遍历权限；fnOS 1.2+ 自定义目录使用系统设置中的文件夹读写授权（含子文件夹和文件）。授权检查使用应用账号实际创建、读写、重命名和删除临时文件，不依赖 -w 的判断结果。

若选择的目录无法创建或写入，启动日志会提示为该目录授权读写。目录初始化日志位于 `TRIM_PKGVAR/directory-setup.log`，运行日志位于 `TRIM_PKGVAR/node-space.log`，均可通过 `/var/apps/node-space/var/` 软链查看。未授权的目录会保留 pending 状态，安装可以完成；不会自动改用其他目录保存笔记。

应用通过 fnOS 统一网关和 Unix Socket 提供访问入口 `/app/node-space`，不监听 TCP 端口。网关入口同时受 fnOS 登录态保护，NoteSpace 自身仍提供账号登录。

飞牛用户隔离以网关注入的 `X-Trim-Userid` 为依据，仅在 Unix Socket 网关模式下采信。每个 UID 使用 `<数据目录>/users/<UID>/` 下的独立笔记、附件、回收站、备份和 SQLite。每位飞牛用户首次进入时单独注册笔记账号；同名账号和会话不会跨用户生效，阅读密码和版本记录也各自独立。旧版根目录下的单用户数据保留原位置，不会自动分配给任何飞牛账号。本地 TCP 开发模式保留原来的单用户数据，不接受请求 Header 伪造飞牛身份。

分享页面由独立的 `frontend/src/views/ShareView.vue` 加载。分享令牌通过持久化索引定位笔记所有者；持有链接及正确分享密码的人可以只读访问该笔记和它引用的附件，无法访问其私人管理接口。分享过期、撤销或笔记加锁后不再可读。飞牛统一网关自身的登录要求仍由系统控制。

后端仅对 `/s/<48位分享令牌>`、对应的 GET 分享正文/附件接口及页面所需的 `/assets/` 编译资源开放匿名访问。其它页面、状态查询、注册和登录都必须带有 Unix Socket 网关注入的有效飞牛 UID；笔记、附件、回收站、版本、设置、备份及分享管理还必须具有该 UID 下有效的 NoteSpace 会话。应用启动健康检查使用每次启动随机生成的内部凭据，不开放匿名探测。安装脚本明确启用 `NOTESPACE_REQUIRE_NAS_USER=1`，缺少 Socket 时拒绝启动。本地 TCP 调试忽略飞牛身份 Header，使用 local 工作空间，仍保留 NoteSpace 密码登录。

如果 fnOS 网关在转发前统一拦截未登录请求，应用代码无法绕过这层限制；真正的免飞牛登录分享需要系统提供分享路由的匿名转发能力。请勿为了开放分享而将整个应用入口改成匿名，或直接公开 Socket/TCP 服务。匿名转发不得采信访问者自行提交的 `X-Trim-Userid` 等身份 Header。

已提供安装引导弹窗（功能介绍、可选数据目录）。仍需在 fnOS 实机验证依赖安装、统一网关路由、应用账号目录权限、启动停止、升级和卸载后的数据保留。
